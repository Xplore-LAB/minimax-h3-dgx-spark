# 架构与优化说明

## 1. 为什么选择 ComfyUI 量化路线

单台 GB10 的优势是 128 GB 统一内存，可容纳大权重；限制是内存带宽、统一内存竞争和长序列 full-attention 开销。官方 4 GPU BF16 路线面向多卡并行，不适合作为单 Spark 首次部署。

量化组合将模型文件控制在约 42.5 GB，为以下内容留下空间：

- 操作系统和 Docker；
- CUDA context；
- Qwen3-VL 编码；
- 视频与音频 VAE；
- diffusion 激活；
- full-attention 临时张量；
- 输出编码和文件缓存。

## 2. 为什么固定 NGC PyTorch 镜像

ARM64 宿主机直接通过 PyPI 安装 PyTorch，可能得到：

- CPU-only wheel；
- 不含 SM121 的 CUDA 构建；
- 与宿主 CUDA/驱动不匹配的版本；
- 被第三方 requirements 无意覆盖的 torch。

NGC Grace Blackwell 容器可降低上述风险，且便于回滚。

## 3. 为什么默认 `cache-none`

H3 的权重已经较大。缓存模型中间结果可提高重复工作流速度，但会挤占统一内存。建立稳定基线时，优先可预测性，而非首轮极限速度。

## 4. 为什么默认不安装第三方节点

第三方节点可能：

- 自动安装并覆盖 torch；
- 编译不支持 SM121 的 CUDA 扩展；
- 引入未经验证的 Triton/SageAttention；
- 改变节点参数或工作流兼容性。

完成官方 T2V 基线后，再按“一次一个节点、单独镜像层、可回滚”的原则扩展。

## 5. 后续优化优先级

```text
P0：稳定运行与可复现
P1：分辨率/时长边界测试
P2：冷启动与热启动测量
P3：SageAttention 的 SM121 源码构建验证
P4：队列、API、鉴权和任务持久化
P5：官方 sparse-attention 权重/实现发布后的升级
```

## 6. 不建议的优化

- 把系统 Swap 当作额外显存；
- 一次性将所有模型常驻内存；
- 用 0.0.0.0 无鉴权暴露公网；
- 在运行容器中随意 `pip install -U torch`;
- 未记录参数就同时修改分辨率、时长和卸载策略；
- 首次测试直接 15 秒、1344×768。
